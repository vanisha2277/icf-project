# ICF Project backend

AI disclosure: parts of this project were built with AI assistance.

This backend serves the reading-support Chrome extension. Some routes are
**deterministic** (no model). Simplification and word definitions use Claude
when `ANTHROPIC_API_KEY` is set.

## What is deterministic (no AI)

- `POST /transform` — bionic reading, sentence chunking, synthetic TTS timings
- Readability scores used to *check* simplifications (`textstat`: Flesch–Kincaid
  grade, Flesch Reading Ease, Dale–Chall, sentence length, syllables/word)

TTS word timings still use the synthetic generator. The Anthropic client is
not used for timings.

## What uses a model

`POST /simplify` is a **four-step pipeline**, not a single “rewrite this” call.

1. **Generate** — Look up the learner profile (`dyslexia`, `adhd`, `esl`,
   `dyscalculia`) in a **curated strategy table**
   (`backend/services/accommodation_knowledge.py`). Those strategy + rationale
   strings are inserted into the system prompt. This is retrieval-grounded
   prompting from a small lookup table, not embeddings or a vector database.
2. **Measure** — Run `textstat` on the original and the rewrite. The model
   does not grade its own work.
3. **Verify** — If Flesch–Kincaid grade did not drop enough (or still misses
   `target_grade_level`), make **at most two** refinement calls that include
   the numeric gap (“still grade 9.2, target is 6.0”). Then measure again.
4. **Fidelity check** — A **separate** model call compares original vs rewrite
   and returns `{ facts_preserved, dropped_information }`. Simplifying must
   not silently drop facts.

Each Claude call has an **8 second timeout**. If generate fails, the request
fails. If refinement or fidelity-check times out, the first rewrite is still
returned with `verification_skipped: true` and `verification_notes` so a live
demo does not hard-fail.

`strategies_applied` in the response is copied from the lookup table, not
generated by the model, so citations stay grounded.

`POST /define-word` explains a word in sentence context, using the same
profile lookup for complexity. Results are cached in memory by
`word + profile + hash(sentence)` so repeat taps in a demo do not re-call
the API.

## Quickstart

```bash
cd backend
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # add ANTHROPIC_API_KEY for simplify/define-word
cd ..
uvicorn backend.main:app --reload --port 8000
```

`GET /health` → `{"status":"ok"}`

Transform (no key required):

```bash
curl -s http://localhost:8000/transform \
  -H 'Content-Type: application/json' \
  -d '{"text":"Hello world. This is a second sentence.","options":{"bionic":true,"chunking":true,"tts_sync":false}}'
```

Simplify (requires `ANTHROPIC_API_KEY`):

```bash
curl -s http://localhost:8000/simplify \
  -H 'Content-Type: application/json' \
  -d '{"text":"Photosynthesis converts light energy into chemical energy.","profile":"dyslexia","target_grade_level":6.0}'
```

Define a word:

```bash
curl -s http://localhost:8000/define-word \
  -H 'Content-Type: application/json' \
  -d '{"word":"chlorophyll","surrounding_sentence":"Plants absorb light using chlorophyll.","profile":"esl"}'
```

## Tests

From the repository root:

```bash
source backend/venv/bin/activate
PYTHONPATH=. pytest backend/tests
```

Default tests **mock** the model. They must pass with no API key.

A live pipeline check (`test_simplify_live.py`) is skipped unless
`ANTHROPIC_API_KEY` is present in `backend/.env` or the environment.

## Environment

- `ANTHROPIC_API_KEY` — required for `/simplify` and `/define-word`
- `ANTHROPIC_MODEL` — optional, default `claude-haiku-4-5` (keeps the 8s timeout realistic)
- `AI_API_KEY` — optional fallback if `ANTHROPIC_API_KEY` is unset

## Notes for judges

- Bionic reading and chunking are pure functions (no external calls).
- Readability verification is formula-based, not the model’s opinion.
- Accommodation explanations are retrieved from a curated table with named
  sources (IDA, BDA, CAST UDL, CHADD, WIDA/TESOL/SIOP, NCTM). That is honest
  retrieval-grounded design, not “full RAG with embeddings.”
- Fidelity check is a second model pass specifically to catch dropped facts.
